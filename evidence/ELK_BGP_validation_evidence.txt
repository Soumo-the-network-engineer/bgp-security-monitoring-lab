BGP SECURITY MONITORING LAB
VALIDATION EVIDENCE
====================

Purpose
-------
This file records representative Elasticsearch query results used to validate
the BGP security monitoring pipeline in the laboratory environment.

Environment
-----------
- Platform: EVE-NG / Cisco IOSv
- Analytics host: BGP-ELK
- Data store: Elasticsearch
- Index family: bgp-routes-*
- Monitored prefix: 100.100.100.0/24
- Legitimate origin AS: 100
- Controlled hijack origin AS: 200
- External route observer: vIOS8 / AS300

1. BASELINE BGP ROUTE VALIDATION
--------------------------------

Query objective:
Verify that normal BGP observations are indexed and that the expected origin
is correctly classified.

Representative result:

{
  "router": "MAIN-INT-RTR",
  "prefix": "100.100.100.0/24",
  "origin_as": "100",
  "security": {
    "origin_match": true,
    "expected_origin_as": "100",
    "event_type": "normal_origin"
  },
  "best": true,
  "tags": ["bgp_route"]
}

Interpretation:
The monitored prefix is normally originated by AS100 and is classified as
normal_origin because the observed origin matches the expected origin.

2. PREFIX HIJACK VALIDATION
---------------------------

Test objective:
Temporarily originate 100.100.100.0/24 from AS200 while AS100 remains the
expected legitimate origin.

Representative detection result:

{
  "router": "MAIN-INT-RTR",
  "prefix": "100.100.100.0/24",
  "origin_as": "200",
  "as_path": "200",
  "security": {
    "origin_match": false,
    "expected_origin_as": "100",
    "event_type": "possible_prefix_hijack"
  },
  "tags": [
    "bgp_route",
    "_possible_prefix_hijack"
  ]
}

Observed Elasticsearch result:
- Matching documents: 18
- Event type: possible_prefix_hijack
- Expected origin: AS100
- Observed origin: AS200
- origin_match: false

Interpretation:
The monitoring pipeline successfully detected the controlled unauthorized
origin and classified the observation as possible_prefix_hijack.

Validation lifecycle:

Normal state
    |
    v
AS200 originates 100.100.100.0/24
    |
    v
possible_prefix_hijack detected
    |
    v
Dashboard metric increases: 0 -> 1
    |
    v
Test route withdrawn
    |
    v
Active hijack state returns to 0

3. ROUTE-LEAK VALIDATION
------------------------

Test objective:
Compare the expected AS path with the path observed by the external AS300
observer.

Expected path:

100

Observed suspicious path:

200 100

Representative detection result:

{
  "router": "vIOS8",
  "prefix": "100.100.100.0/24",
  "origin_as": "100",
  "as_path": "200 100",
  "possible_route_leak": true,
  "security": {
    "event_type": "possible_route_leak",
    "as_path_match": "false",
    "expected_as_path": "100"
  },
  "tags": [
    "bgp_route",
    "vios8_route",
    "_possible_route_leak"
  ]
}

Observed Elasticsearch result:
- Event type: possible_route_leak
- Expected AS path: 100
- Observed AS path: 200 100
- as_path_match: false
- possible_route_leak: true
- Router: vIOS8
- Origin AS: 100

Interpretation:
The route-leak detection logic identified an unexpected intermediate AS in
the observed path while retaining AS100 as the legitimate origin.

4. VALIDATION SUMMARY
---------------------

| Test Case       | Expected             | Observed              | Result |
|----------------|----------------------|-----------------------|--------|
| Normal origin  | Origin AS100         | Origin AS100          | PASS   |
| Prefix hijack  | Origin AS100         | Origin AS200          | PASS   |

End-to-end validation confirms that the lab can:
1. Collect BGP route state.
2. Normalize routing observations.
3. Compare observed values against expected security baselines.
4. Classify abnormal origin and AS-path behavior.
5. Index security events in Elasticsearch.
6. Expose the resulting state to Kibana for visualization.
